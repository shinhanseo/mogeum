# 개발 순서와 멘토 데모

목표: 사용자가 기록한 느낌이 AI 취향 요약을 만들고, 메뉴판 속 처음 보는 술의 선택으로 연결되는 동작을 보여준다. **취향 요약과 메뉴판 분석은 출시 전 필수**다. 정확한 일요일 날짜는 아직 미확정이므로 이 문서와 GitHub milestone에 임의의 due date를 지정하지 않는다.

## 작업 순서

| 단계 | 완료 상태 |
|---|---|
| M0 · 기록의 실제 저장 | 앱 초기 설정·공통 UI·DB/RLS·인증 → 사진 기록 저장·재실행 복구 → 노트·술장·검색·상세·수정·삭제·재음용 |
| M1 · 근거 있는 개인화 | AI 공통 계약·제품 특징/출처 → 초기/축적 취향 요약·근거 보기. OCR 엔진 검증은 이 단계 이전부터 짧게 진행 |
| M2 · 여러 장 메뉴판 추천 | 사진 관리·기기 OCR → 서버 메뉴 해석·중복/판매 단위 구분 → 사용자 확인 → 새로운 술 추천 → 비교·원본 위치 |
| M3 · 두 플랫폼 데모·베타 | 전체 흐름 검증·AI 품질 평가·권한/네트워크/실패 처리·테스터 빌드·출시 준비 |

첫 목표는 사진 한 건이 실제 Storage/DB에 저장되고 술장에 나타나는 것. 공통 컴포넌트와 스키마 계약은 초기에 잡되 전체 화면을 먼저 mock으로 완성하는 것을 목표로 삼지 않는다.

## 일정 운영

정확한 마감 확인 후 작업별 의존성과 남은 시간을 기준으로 issue/milestone due date를 갱신한다. 마감 직전 3일은 새 기능보다 오류 수정·실기기 검증·배포 빌드에 확보한다. 기술 검증이 지연되면 OCR 엔진 교체나 제한된 제품 카탈로그 등 범위를 좁히는 결정을 제안하되 필수 AI 흐름을 말없이 삭제하지 않는다.

## 멘토 데모 시나리오

1. 테스터가 사진만으로 술 기록을 저장하고 앱을 재실행해 확인한다.
2. 질문에 간단히 답하고 다시 마시고 싶은지 남긴다.
3. 초기/충분한 기록 상태를 구분해 AI 요약과 실제 근거를 연다. 충분한 기록은 명시된 demo account의 합성 seed를 사용할 수 있으나 예시임을 밝힌다.
4. 메뉴판 3장을 기기 OCR하고 수정 화면에서 이름·가격·용량을 확인한다.
5. 겹친 메뉴와 잔/보틀을 구분해 합친 목록으로 추천한다.
6. 처음 보는 술의 닮은 향과 다른 마무리, 내 기록, 외부 출처, 원본 메뉴 위치를 확인한다.
7. 한 장 실패·수정 후 stale 추천·재시도를 짧게 보여준다.

## 첫 사용자 100명

배포 링크·피드백 창구와 함께 실제 설치/기록 생성/노트 작성/재방문/추천 실행을 개인정보 최소화 방식으로 관찰한다. 목표는 100개의 계정 생성만이 아니라 핵심 흐름을 쓴 사용자를 모으는 것이다. 이벤트 정의는 구현 이슈에서 정하고 원문 메모나 사진을 분석 이벤트에 보내지 않는다.
