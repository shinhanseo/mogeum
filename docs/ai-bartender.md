# AI 바텐더 · 첫 연결판

2026-11-05 · #222. 기존 Supabase/Gemini를 재사용한다. 별도 AI 서버·벡터 DB·자체 모델을 추가하지 않는다.

## 사용자 흐름

홈의 ‘오늘의 한 잔, 함께 골라볼까요?’ → 바텐더. 시작 선택지 또는 자유 입력으로 대화를 시작한다. 필요한 질문은 모델이 한 번에 하나씩 묻고, 추천 한 잔을 먼저 보여준다. 나머지 후보는 펼쳐서 볼 수 있다. ‘다른 술로’, ‘더 가벼운 걸로’, ‘다른 주종’으로 조정하거나 직접 입력한다. 공통 카탈로그 제품은 기존 durable wishlist 저장을 사용한다. 내 기록의 근거와 제품 원문 링크를 확인할 수 있다.

- 처음 사용자: 오늘의 선택으로 고른 **후보**. 개인 기록으로 확인한 취향으로 포장하지 않는다.
- 기존 사용자: 확정된 감각 답변과 명시적 호감을 집계해 비교한다. 사진만 있는 기록은 맛 근거가 아니다.
- 새로운 이름의 술: 모델이 조사할 이름·주종·판본을 제안 → 사용자가 ‘정보 찾아보기’를 눌러야 검색한다. 서버가 기존 공유 캐시/검색 예산/제조사 원문 대조를 재사용한다. 검증을 통과한 **제품 후보**만 보여주며 verified 카탈로그나 wishlist에 자동 등록하지 않는다.
- 이름이 현재 읽은 후보 범위 밖이어도 공통 카탈로그에서 문자열이 명시적으로 일치하면 후보 우선순위를 올려 불필요한 재검색을 줄인다.

## 비용과 요청 경계

`POST /functions/v1/bartender`는 JWT를 Auth.getUser로 확인한다. body는 operationId, revision, action(say/research), text만 허용한다. owner/model/budget/검색 query를 클라이언트가 지정할 수 없다.

일반 메시지는 `gemini-3.5-flash-lite` 한 번 호출한다. 조건 추출, 짧은 응답, 제품 ID 선택을 한 번의 구조화 출력으로 받는다. 검색 도구를 이 호출에 붙이지 않는다. 서버에서 출처 있는 제품 특징과 기록 ID를 조합해 추천 카드를 만든다. 모델이 새 제품 ID/감각 ID/근거 ID를 직접 만들어 반환할 수 없다.

입력은 최대 800자, 모델 입력 데이터 최대 UTF-8 16KB, 최근 대화 6개, 집계 감각 12개, 주종별 제품 최대5개(총20개), 출력 최대1200토큰, 자동 provider retry 0회다. 모델 사용 토큰은 완료 영수증에 보관한다. 한국어 응답은 짧게 지시하나 응답 품질은 계속 평가해야 한다.

DB 전역 lock으로 사용자당 UTC 하루30회·전체1000회까지 예약한다. 실패한 provider 시도도 차감한다. 일반 텍스트 시도당 $0.01을 보수적 예산 단위로 기록한다. 이는 실제 청구액이나 검색 비용을 합산한 결제 한도가 아니다. 모델 단가 변경 시 다시 검토해야 한다. 검색은 기존 공유 예산(하루20·월200 신규 작업, 동시2개와 provider backoff)도 추가로 적용한다. 캐시는 최대7일 재사용한다. 조사 파이프라인은 검색+특징 추출 등 여러 호출을 사용할 수 있으므로 일반 채팅 1회와 비용을 구분한다.

같은 operationId+본문+revision은 기존 영수증을 반환한다. 실행 중에는 추가 모델 호출을 막고, 다른 본문으로 operation ID를 재사용하면 conflict다. 완료된 대화 revision과 맞지 않는 새 요청도 차단한다. 응답이 유실되면 기기의 계정별 pending 요청으로 같은 요청을 재확인한다. 임의로 자동 재전송/자동 검색하지 않는다.

## 저장·보안

- 서버: 사용자별 조건, 최근 최대12개 메시지(총30KB 초과 시 이전 쌍부터 제거), 조사 제안과 최근 추천. 오늘 조건과 개인 기록 집계는 분리한다. 대화를 장기 취향 DB로 자동 승격하지 않는다.
- 이전 추천과 기록 snapshot이 달라지면 앱은 이전 카드를 숨긴다. 다음 응답은 최신 기록을 조회한다.
- private 테이블은 RLS + client 권한 차단. 조회/비우기는 auth.uid RPC, 생성/확정·예산은 service_role RPC만 실행한다.
- 초기화는 일일 한도를 초기화하지 않는다. 계정 삭제 시 대화·요청은 FK cascade, 개인별 사용량은 auth.users 삭제 trigger로 지운다.
- 중복 복구 영수증은 새 요청 시 24시간 이전분을 정리한다. 일일 사용량은 새 요청 시 30일 이전분을 정리한다. 비활성 기간에는 정리가 다음 요청까지 지연될 수 있다.
- 기기에는 계정별 미확인 전송만 저장한다. 계정 삭제의 로컬 freeze/cleanup 대상에 포함한다. 키/세션/사용자 노트를 로그로 출력하지 않는다.

## 디자인·현재 제약

새 바텐더 전용 Figma 확정 프레임은 없다. 사용자와 검토한 PNG 방향을 기존 ScreenHeader/Button/ChoiceChip/DrinkArt와 tokens.ts로 구현한 **신규 확장 UI**다. 이전 04 질문 원본(4:3689·4:3737 등)과 같은 컴포넌트를 재사용하며 Figma 픽셀 일치라고 주장하지 않는다. 해달은 이전 캐릭터 시안을 단순 벡터로 구현했다. 키보드/입력/버튼은 네이티브 컴포넌트다.

현재는 제품 가격·판매처 재고 데이터가 없어 예산 충족을 보장하지 않는다. 음식 페어링도 검증된 별도 지식이 없어 확정하지 않는다. 미등록 후보는 이름/연산/빈티지 확인이 필요하며 검색 성공을 보장하지 않는다. 검색 후보를 개인 관심 목록에 직접 보관하는 별도 스키마는 이번 첫 연결판에 포함하지 않았다. 기록 작성으로의 자동 follow-up, 장기 대화 기억·음성·공개 리뷰 조회는 구현하지 않았다.
