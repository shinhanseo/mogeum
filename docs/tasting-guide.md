# 질문형 노트 계약

최신 기준은 GitHub #6과 Figma `04 · 화면 정리본`이다. 아래는 구현 계약이며 아직 질문 화면 전체가 앱에 연결되었다는 뜻은 아니다.

## 진입

기본 기록에서 재음용 의향(또 마시고 싶어요 / 괜찮아요 / 내 취향이 아니에요)을 선택하고 별점은 선택적으로 남긴다. 기본 저장 후 동일 record ID에 노트를 보충한다. 재음용 의향은 마지막 질문으로 반복하지 않는다.

첫 노트는 ‘어떻게 남길까요?’ 바텀시트에서 가볍게/자세히만 선택한다. 이미 선택한 주종을 다시 묻지 않는다. 다음 새 노트는 마지막 사용 모드를 사용하며 기존 노트는 해당 노트 모드를 우선한다. 모든 질문은 건너뛸 수 있다.

| 주종 | 가볍게 | 자세히 |
|---|---:|---:|
| 위스키 | 5 | 9 |
| 와인 | 5 | 11 |
| 맥주 | 5 | 10 |
| 전통주 | 5 | 8 |

미리보기·문장 편집은 질문 수에 포함하지 않는다. 가벼운 질문의 정확한 문구와 UI 수치는 원본 프레임을 확인한 뒤 구현한다.

## 심화 질문 순서

- 위스키: 마신 조건 → 색 견본 → 처음 향 → 맛 → 바디·질감 → 알코올 자극 → 마신 뒤 올라오는 향 → 여운 → 전체 인상.
- 와인: 마신 조건 → 유형별 색·농도·투명도 → 처음 향 → 향 변화 → 단맛 → 산미 → 탄닌 → 바디·질감 → 알코올·탄산 → 여운 → 전체 인상. 빈티지는 기본 정보이며 질문 수에 포함하지 않는다.
- 맥주: 마신 조건 → 색·투명도 → 거품 → 향 → 맛 → 탄산 → 바디·질감 → 알코올 자극 → 여운 → 전체 인상.
- 전통주: 세부 주종·조건 → 향 → 단맛 → 산미·감칠맛 → 바디·질감 → 탄산 → 알코올 자극 → 여운.

독립적인 강도는 각각 저장한다. 실제 도수와 체감 자극을 섞지 않는다. 색으로 숙성연수·품질·맛을 추정하지 않는다. 관찰하지 않은 향 변화·거품은 채우지 않는다.

## 향 선택

위스키·와인·맥주는 계열 복수 선택 후 선택한 모든 계열의 세부 향을 카탈로그 순서로 펼친다. 계열만 선택해도 답변이며 세부 향을 자동 선택하지 않는다. 계열을 해제하면 해당 세부 향을 생성·분석에서 제외하되 작성 draft에는 보존하고 재선택 시 복원한다.

‘향을 구분하기 어려워요’는 계열·세부 향·자유 입력과 배타적이다. 향의 선명함은 독립적으로 기록한다. 처음 향/마신 뒤 향/시간 경과 후 향은 서로 별개 관찰이다. 정확한 descriptor code 목록은 `src/features/tasting/catalog.ts`에 정의한다.

## 데이터와 문장

unanswered / skipped / unknown / none / answered와 강도 0을 구분한다. question ID, descriptor code, 모드, 카탈로그 버전을 저장한다. 한국어 표시 문구나 배열 위치를 ID로 쓰지 않는다. 새 카탈로그 버전은 2이며 구버전 답변을 위치로 강제 변환하지 않는다.

모드 전환은 양쪽 draft를 보존하고 활성 모드만 생성·분석에 보낸다. 명확한 매핑 없이 답변을 자동 확장하지 않는다. 원래 선택값과 확정 문장은 별개다. 직접 수정한 문장을 자동 덮어쓰지 않는다. 계열 수준 선택을 세부 향으로 확장하거나 전체 선호를 특정 향 선호로 해석하지 않는다.

## 구현 상태 · 2026-10-22

4주종 가볍게 20개·심화 38개 질문을 정적 버전 2 카탈로그로 구현했다. 원본 프레임 ID를 각 질문에 보관한다. `light.json`/`deep.json`의 code는 저장 식별자다. 문구 번역 시 code를 바꾸거나 배열 순서로 다시 부여하지 않는다.

`TastingComposer`는 기본/선택/모름/건너뜀, 모드 전환과 본문 스크롤·키보드 보정을 공유한다. 와인 색 종류 전환과 관찰하지 않은 향 변화의 숨겨진 응답은 `serializeAnswers()`에서 제외한다. 기기 임시 저장은 사용자+기록별로 직렬화하고, 저장 응답이 불확실하면 원래 operation ID·revision·문장을 보존해 같은 요청으로 재시도한다.

기본 저장 버튼과 저장 후 노트 버튼을 분리했다. 후자는 기본 기록 저장 성공 후 같은 record ID로 이동한다. 첫 모드 선택, 마지막 사용 모드, 저장된 v2 노트의 모드·답변 복원을 연결했다. 원자적 노트 확정 RPC도 개발 Supabase에 적용했다. 실제 소셜 로그인은 provider 미등록으로 아직 검증하지 못했다.

미리보기는 결정적 템플릿을 사용한다. LLM 호출을 완료했다고 표시하지 않는다. 기존 직접 편집 문장은 재정리 전에 유지/다시 정리를 선택하고, 편집 중 임시 문장과 적용한 문장을 구분한다.

이슈 #6/#27 전체 완료는 아니다. 구버전 카탈로그 1의 읽기/수정 UI, 의미가 같은 답변의 명시적 모드 매핑, 상세 화면 진입/오래된 revision 충돌 복구 UI와 전 플랫폼 검증은 남아 있다. Figma에 없는 이슈 세부 항목(예: 맥주 거품 질감, 위스키 외관 추가 메모)은 이번 화면에 임의로 추가하지 않았다. [검증 기록](verification/tasting-notes.md)을 참고한다.
