# Android 실기기 수동 QA

대상: 갤럭시 S24(SM-S921N), Android 16. 내부 베타 `com.hanseo.mogeum`은 개발 앱 `com.example.mogeum.dev`와 별도 설치된다. 베타 APK는 Metro/Expo 주소 없이 실행한다. 기존 개발 앱을 삭제하거나 데이터를 초기화할 필요가 없다.

## 이미 확인한 범위와 남은 범위

| 구분 | 확인된 증거 | 이 증거로 완료 처리하지 않는 항목 |
| --- | --- | --- |
| 초안 저장소 | API37 개발 빌드에서 앱 프로세스 종료 후 4주종×2방식×3단계, 24개 합성 초안 복구 | 갤럭시 터치 입력부터 복구까지의 실제 화면 흐름 |
| 노트 입력 | iOS 한국어 입력/Done, 작은 화면 긴 한글, 빈 편집 재실행 복구 | 삼성 키보드 Done/조합 중 글자/다른 키보드 |
| 기본 저장·노트·OCR | 별도 native/서버 합성 회귀와 권한 경계 검사 | 갤럭시 실사 사진·카메라·저조도 메뉴판·UI 전체 연결 |
| 계정 | 기존 iOS 소셜 로그인과 합성 삭제 회귀 | Android 소셜 로그인/복귀, 실제 Apple·카카오 grant 해제 |

Android Studio 조작 도구에서 터치가 전달되지 않아 아래 항목은 직접 확인할 목록이다. 설치·실행 확인만으로 체크하지 않는다.

## 먼저 해볼 핵심 6개

- [ ] **실행·로그인**: 홈 화면의 `모금 베타`를 열어 카카오로 로그인한다. 개발 서버 주소를 묻지 않고, 로그인 후 술장이 보여야 한다. 앱 종료·재실행 뒤 계정이 유지되는지 확인한다.
- [ ] **기본 저장**: 가운데 `+` → 사진/이름/주종/날짜 → 간단한 감상 → 저장한다. 술장에서 상세를 다시 열어 값과 사진 비율을 확인한다. 같은 술을 한 번 더 남겨 날짜별 기록이 합쳐지는지도 본다.
- [ ] **키보드·빈 입력**: 노트 직접 입력에 긴 한글을 적고 키보드 `완료`를 누른다. 키보드만 닫히고 내용은 유지돼야 한다. 선택한 답변을 해제하고 입력도 모두 지운 다음 진행해 `Non-answer contains observations` 같은 오류가 나오지 않는지 본다.
- [ ] **질문 중 재실행**: 저장된 기록의 노트를 열어 선택 답변과 메모를 남기고 2~3번 질문에서 앱을 완전히 종료한다. 다시 켜서 같은 기록의 노트를 열면 마지막 단계와 답변이 유지돼야 한다. 앱 시작이 술장인 것 자체는 오류가 아니다.
- [ ] **문장 편집 중 재실행**: 미리보기 → 직접 수정 → 문장을 모두 지움 → 앱 종료·재실행 → 같은 기록의 노트. 빈 편집 화면이어야 한다. `취소`하면 원래 미리보기 문장으로 돌아와야 한다.
- [ ] **오프라인·재시도**: 작성 내용을 만든 뒤 휴대폰의 Wi-Fi/모바일 데이터를 잠시 끄고 저장한다. 오류 안내가 보이고 내용이 보존돼야 한다. 연결을 복구해 재시도한 뒤 중복 기록 없이 저장되는지 확인한다. 긴 노트에서도 실패 안내가 화면 아래에 숨지 않아야 한다.

## 이어서 볼 항목

- [ ] **시스템 뒤로 가기**: 키보드가 있으면 먼저 키보드를 닫고, 질문에서는 이전 질문/적절한 이전 화면으로 이동하는지 본다. 미리보기·편집·바텀시트에서도 작성 내용이 사라지지 않는지 확인한다.
- [ ] **Done 전체 입력**: 술 이름, 기본 정보 수정, 술장 검색, 다른 술로 옮기기 검색/새 이름, 메뉴명·가격·용량 수정에서 완료가 불필요한 저장/다음 화면 이동을 일으키지 않는지 본다. 숫자 키보드도 닫을 수 있어야 한다.
- [ ] **권한 거부**: 카메라 안내에서 나중에/OS 거부를 선택해도 기존 입력은 남아야 한다. 거부 후 카메라를 다시 열면 설정 안내가 보이고, 설정에서 허용 후 돌아왔을 때 촬영이 가능한지 확인한다. OS 권한창 디자인은 Android 자체 화면이다.
- [ ] **앨범 취소·사진 교체**: 앨범 선택을 취소하면 원래 사진이 유지돼야 한다. 다른 사진을 선택해 교체 저장하면 상세/술장에 반영되고 세로 사진이 가로로 늘어나지 않아야 한다.
- [ ] **사진·카메라**: 실제 촬영의 회전 방향, 세로/가로 비율, 큰 사진, 누끼 원본 전환을 확인한다. 투명 잔·어두운 병 라벨의 누끼 결과도 확인한다.
- [ ] **기록 이동**: 기록 한 건을 다른 술로 옮긴 뒤 날짜/평가/노트가 유지되는지 본다. 검색어를 빨리 바꿔도 이전 검색 결과가 새 결과를 덮지 않아야 한다.
- [ ] **주종별 화면**: 위스키·와인·맥주·전통주 각각 가볍게/자세히의 질문을 열어 긴 선택지가 잘리지 않는지 본다. 와인은 레드/화이트/로제 견본이 바뀌고 이전 선택이 다른 종류의 색으로 잘못 적용되지 않아야 한다.
- [ ] **메뉴판 여러 장**: 실제 메뉴판 2~5장을 추가하고 한 장 취소/교체 후 읽은 항목을 확인한다. 이름·가격·잔/병 용량을 수정하고 추천을 받는다. 추천 원본 위치가 해당 사진의 항목과 맞는지 본다. 실사 OCR 오탈자는 수정 전후를 나눠 기록한다.
- [ ] **취향 근거**: 사진만 있는 기록을 향·맛 취향으로 단정하지 않는지, 노트가 있는 기록이 요약/새로운 술 추천의 근거로 연결되는지 확인한다. 근거 부족은 추천처럼 꾸며 나오지 않아야 한다.
- [ ] **로그아웃·계정 경계**: 저장 후 로그아웃하면 개인 술장/근거 사진이 남아 보이지 않아야 한다. 다른 계정이 있으면 전환해 이전 계정 초안/기록이 섞이지 않는지 본다. 평소 계정으로 계정 삭제를 시험하지 않는다.
- [ ] **접근성·화면**: 시스템 글자 크기를 크게 한 경우와 기본 크기에서 버튼 중앙 정렬, 하단 +/하트, 키보드 위 입력창, 긴 한글/제목, 하단 안전 영역을 확인한다.

## 결과 남기기

문제가 생기면 아래 형식으로 알려주면 된다. 스크린샷은 계정/개인 기록을 가리고, 인증 코드·비밀번호는 보내지 않는다. 앱을 지우거나 데이터를 초기화하면 복구 문제의 원인이 사라질 수 있으니 먼저 재현 순서를 남긴다.

```text
빌드 번호:
기기/OS/키보드:
진행한 순서:
기대했던 동작:
실제 동작:
재현 횟수:
온라인/오프라인:
```
