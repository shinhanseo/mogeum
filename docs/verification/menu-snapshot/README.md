# 메뉴 추천 중 기록 변경 차단 · 2026-10-26

기존 메뉴 추천 서버는 취향 context를 한 번 읽고 결과를 만들었다. 읽은 직후 다른 기기에서 기록이 수정되면 응답의 근거가 이미 오래된 상태일 수 있었다. 다음 한 잔에서 사용하던 snapshot guard를 메뉴 결과 생성에도 적용했다. 생성 전·후 입력 hash와 totalRecords를 비교하고 바뀌면409/MENU_EVIDENCE_STALE로 결과를 폐기한다. 자동 재추천/추가 AI 호출을 하지 않는다.

앱은 이 허용된 코드를 기존 stale 추천 안내에 연결하며 사진·메뉴 입력을 보관한다. 기존 메뉴판 화면 레이아웃·Figma 컴포넌트는 변경하지 않았다. 클라이언트의 근거 이미지 갱신 단계 재확인도 유지한다. 두 번째 확인 이후의 모든 미래 변경까지 막는 락은 아니며, 화면 복귀 시에는 계속 최신성을 확인해야 한다.

실제 결과 생성 helper에 정상 감각 근거와 제품 메뉴를 넣어 전체 메뉴 응답 계약 검증, 기록 편집·추가·삭제 버전 변경 차단, 마지막 context 읽기 실패 시 결과 폐기를 확인했다. check346개 중338개 통과/환경 의존8개 skip, Deno menu endpoint check 통과.

개발 프로젝트에 CLI source를 배포하고 [관리형 synthetic 검증](managed-report.json)에서2장12메뉴·메뉴 저장 재시도·타인 접근 차단·추천1개·모호한 가격 미확정·다음 술19개·계정 정리를 확인했다. AI 생성은 명시적으로 제외했다. 관리형에서 동시에 기록을 수정하는 fault injection이나 native 전체 UI 검증을 수행한 것은 아니며 해당 경합 검증은 helper의 제어된 context 변경 회귀다.
