# 다음 한 잔 7일 생성 예약 기반 · 2026-10-28

서버 전용 private.discovery_generations와 begin/finish_discovery_generation RPC를 추가했다. 사용자 한 명당 한 행으로 주종/기기별 우회를 막고, 동시 예약은 사용자 advisory lock과 행 잠금으로 합친다. 성공 완료 시각부터168시간 동안 동일 입력/계약은 캐시를 반환한다. 근거 hash가 달라지면 기존 결과를 반환하지 않고 invalidated와 다음 생성 가능 시각만 돌려준다. 이 경우에도 성공 슬롯의 기한을 당기지 않는다.

실패 완료는 성공 시각을 만들지 않고60초 대기만 둔다. 미완료 lease는90초 후 회수한다. 다른 lease와 만료 lease는 완료할 수 없다. 같은 성공 payload의 완료 재전송은 true를 반환하되 생성 시각/다음 시각을 이동하지 않는다. JSON은 객체/128KB 이하로 제한하고 사용자 삭제 시 FK cascade로 개인 결과도 지운다. 일반 사용자·익명은 RPC/테이블에 접근할 수 없다.

전체 migration을 별도 임시 PostgreSQL에 재생한 테스트34/34통과. 두 독립 DB 세션의 동시 요청이 acquired/running 하나씩임을 확인했다. 계정별 독립,7일 간격,입력 변경 후 결과 비공개,완료 멱등,실패 대기,만료 회수,사용자 삭제 cascade도 검증했다. 임시 DB는 테스트 후 정리했다. PGlite는31통과/독립 세션3제외.

현재는 DB 예약 기반만 구현했다. next-drinks 함수/앱에는 아직 연결하지 않았고 기존 evidence-rules-v1 동작도 그대로다. Gemini 검색 모델은 별도 설정 검증이 필요하다. 검증된 결과 schema, 최신 저장/음용/숨김 필터와 현재 근거 재검증,생성 중 기록 변경,소스 revision 변경 처리,앱의 다음 갱신 시각 표시를 연결한 후 기능 완료로 판단한다. #176을 닫지 않는다.

## 캐시 복원 계약

weekly-selection-v1은 최대24개 제품 ID만 보관한다. 임의 제품·중복·모델 생성 문구는 받지 않는다. 캐시를 다시 보여줄 때 현재 검증 카탈로그와 현재 기록에서 비교 근거를 재계산하므로, 저장/음용/제품 비공개/긍정 근거 삭제나 부정 변경은 즉시 제외한다. 빠진 슬롯을 새 제품으로 채우지 않으며 주종 필터는 생성 묶음을 바꾸지 않는다. 아직 함수 연결 전 순수 도메인 계약이다. 신규 계약/생성 조율 테스트3/3통과. 생성 도중 근거 변경과 공급자 실패는 결과를 확정하지 않고 실패 완료로 정리한다. 전체 check433통과/환경14제외.

## Gemini 선택 adapter

SDK 구조화 출력으로 근거가 있는 후보 최대80개 중 최대24개 ID를 선택한다. 모델에는 제품 ID/주종/근거 집계만 전송하며 개인 기록 ID·술 이름·노트 원문·사진 URL을 보내지 않는다. 추가 검색은 하지 않는다. 존재하지 않는 제품/중복/문구 추가는 거부한다. SDK transport/서버 예약 연결 테스트4/4로 요청 본문과 임의 제품 거부를 확인했으며 실제 Gemini 호출 및 함수 연결은 아직 하지 않았다. 이는 검증 카탈로그 내 우선순위 선택 adapter이고 신규 제품 발굴은 별도 검색·원문 검증 파이프라인이다.

weekly-service는 검증된 owner와 서버 계산 후보만 받는 내부 adapter다. 키 누락은 예약 전에 종료하고 진행 중 예약은 모델 호출 없이 합류한다. 공개 endpoint 연결은 다음 단계다.

## 별도 버전 API 연결

next-drinks에서 shared-catalog-v1과 recommendationVersion=weekly-selection-v1을 함께 보낸 경우만 새 생성 경로를 선택한다. 기존 앱/구버전은 evidence-rules-v1을 유지한다. 사용자 ID는 검증한 JWT에서 가져오고 서버 생성 예약은 service-role 내부 호출로만 수행한다. 필터 전 전체 주종 후보로 한 번 생성하고 결과에만 주종 필터를 적용한다. 기록 부족은 모델 없이 insufficient, 공급자 키 누락은 예약 전에503 AI_NOT_CONFIGURED다.

생성/캐시 복원 전후 개인 snapshot을 확인하고 추가로 카탈로그/저장 목록을 다시 페이지 조회한다. 중간 변경은409로 이전 결과를 숨긴다. 이는 응답 이후 실시간 구독을 보장하지 않는다. 현재 앱은 새 버전을 아직 요청하지 않는다. 실제 Gemini 생성·저장·다른 기기 캐시 재사용은 추가 검증해야 하며 완료로 처리하지 않았다.

로컬 실제 Auth/Data API/RPC와 Gemini SDK의 합성 transport를 연결해 generated → cached → 입력 변경 invalidated를 확인했다. 모델 요청은 최초1회였고 임시 사용자는 테스트 후 삭제해 개인 캐시 cascade도 적용했다. 실제 Gemini 호출은 아니다. 성공 직후 서버의 완료 영수증을 다시 읽어 생성 시각/다음 갱신 시각을 반환하며 기기 시계로 기한을 계산하지 않는다. 관리형 개발 DB에는 CI 통과한20261028030000 migration만 적용했다. 앱 새 버전 전환·실제 제공자 E2E 전에는 새 endpoint를 관리형 서버에 배포하지 않았다.
