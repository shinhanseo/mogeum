# 노트 초안의 입력·복구·정리 순서

기존 persistence는 쓰기끼리만 직렬화했다. 화면을 닫고 다시 열면 앞선 입력 쓰기가 끝나기 전에 restore가 예전 값을 읽을 수 있었다. clear도 현재 큐를 기다리는 동안 추가된 쓰기와 독립적으로 실행되어 새 초안을 지울 수 있었다. 빈 문자열은 저장소에 요청이 없는 것으로 취급했다.

`createTastingDraftStorage`가 owner+record별 읽기·쓰기·정리를 모두 같은 큐로 실행한다. 읽기는 앞선 입력을 기다리고, 실패한 이전 쓰기는 이후 복구를 영구 차단하지 않는다. null만 없는 초안이다. 빈 문자열/손상 JSON은 오류를 반환하고 원문을 보존한다.

노트 서버 저장 후 clear는 저장한 frozen draft와 현재 원문이 같을 때만 지운다. 다른 초안이면 보존하고 저장 화면에 실패가 전달되어 무조건 detail로 빠져나가지 않는다. 기록 자체를 명시적으로 삭제한 경우의 기존 무조건 초안 정리는 유지한다. UI 레이아웃·문구·질문과 DB schema/RPC 변경 없음.

검증: `npm run check` 269개 중 263 통과, 환경 의존 6개 skip. 지연된 실제 storage port를 제어하는 테스트로 입력 완료 전 복구 대기, 새 초안 보호, clear 뒤 새 입력 유지, 빈/손상 원문 보존, 쓰기 실패 후 회복을 확인했다. 네이티브 AsyncStorage 지연이나 강제 종료를 이번에 새로 강제한 시험은 아니다.
