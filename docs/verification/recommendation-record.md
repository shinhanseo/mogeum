# 추천 → 마셔본 한 잔 기록

2026-11-06. 추천 목록과 추천 이유에서 `마셔봤어요 · 기록하기`를 제공한다. 마셔보고 싶은 술의 기존 기록 진입도 같은 문구로 통일한다. `/record?productId=...`에 제품 ID만 넘기고 인증된 계정으로 verified 카탈로그 정보를 다시 조회한다. 이름·주종과 명시된 와인 빈티지만 채우며 사진·호감·별점·감각은 자동 생성하지 않는다. 기존 기록 화면에서 이름과 종류 수정, 사진 추가, 기본 저장 또는 질문 노트 추가로 이어진다.

추천에서 진입해도 기존 제품별 작성 초안 복원과 중복 저장 방지 계약을 사용한다. 버튼을 누른 시점에는 위시리스트를 삭제하거나 마신 기록을 만들지 않는다. 실제 저장은 기존 저장 버튼으로 확정한다. 사진 없이도 저장할 수 있다. 추천 화면 로딩·오류·저장 중에는 진입 버튼을 비활성화한다.

검증:
- 전체 npm run check (최종 로그 `/tmp/mogeum-record-final-check.log`).
- 로컬 격리 Supabase에서 `MOGEUM_TEST_SUPABASE_HTTP=1 npx tsx --test tests/recommendation-record-api.test.ts` 통과. 임시 인증 사용자로 4주종 제품 조회→실제 기록 저장→동일 요청 재전송→총 4기록 유지 확인 후 사용자 삭제.
- iOS 시뮬레이터의 기존 합성 추천 이유 시안에서 하단 두 버튼 배치 확인. 신규 버튼은 기존 Button/토큰을 사용하며 신규 Figma 변경 또는 원본 일치 검증은 하지 않았다.
- 별도 기존 next-drinks 통합 테스트는 로컬 Edge 함수가 인증 검사 전에 503을 반환하여 실패했다(예상401). 이번 기록 연결 전용 테스트는 Edge 함수를 경유하지 않고 제품 RLS/기록 RPC를 검증하므로 해당 통합 장애를 해결했다고 보지 않는다.
- 이번 변경의 Android 실기기 터치 검증은 미실행.
