# 동적 카탈로그 → 다음 한 잔 · #175

추천 API의 새 `shared-catalog-v1` 계약은 활성 계정의 RLS로 읽은 `product_catalog.status=verified` 문서를 사용한다. DB에 검증 제품을 추가하면 앱 재배포 없이 추천 비교·이유·저장 목록에서 사용할 수 있다. 현재 데이터는 여전히 32제품이며 120제품군 확보는 별도다.

- 신규 앱은 요청에 `catalogVersion: shared-catalog-v1`을 보낸다. 응답의 catalog 문서를 형식/출처 URL/ID/중복/크기 검사하고 추천의 제품 사실이 해당 문서와 정확히 같은지 확인한다. 감각 근거·반대 근거·점수 검사는 유지한다. 형식 검사는 사실 확인을 대체하지 않는다. 사실 신뢰 경계는 인증된 서버와 verified 승격 권한이다.
- 구버전 앱의 버전 없는 요청에는 기존 정적 문서 계약을 제공한다. DB에서 verified인 기존 ID만 비교하며 새 제품의 북마크는 구버전 응답에만 생략한다. DB의 북마크를 삭제하지 않는다. 신규 앱에는 다시 표시된다. 메뉴판 API는 아직 구계약이다.
- 서버 카탈로그/북마크 및 앱 북마크 재조회는 ID cursor로 200개씩 읽는다. 카탈로그 1,000개, 북마크 상태 10,000개 상한 초과 시 조용히 일부를 반환하지 않고 실패한다. 서버 조회 전체 25초·앱 북마크 재조회 전체 30초 제한이다.
- 저장 목록은 응답의 검증 제품을 사용한다. 보류된 제품의 북마크 ID는 유지하고, 숨긴 제품 사실을 노출하지 않는 ‘제품 정보 확인 중’ 행에서 해제할 수 있다. 이 행은 기존 토큰/행/버튼을 재사용한 추가 상태이며 Figma 원본 일치 검증을 주장하지 않는다.
- 기록하기는 productId만 전달하고 RLS로 해당 검증 제품을 다시 읽어 이름·주종·와인 빈티지만 채운다. 평점/감각을 복사하지 않는다. 보류/누락/실패 시 빈 정보를 꾸며 채우지 않는다. 복구한 개인 초안과 미완료 저장 요청이 우선이다.
- 표시 후 보류되어 새 저장이 명시적으로 거부되면 요청을 재적용하지 않고 최신 상태를 읽어 큐를 해제한다. 응답 유실은 계속 같은 작업으로 복구한다.
