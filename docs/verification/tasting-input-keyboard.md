# 테이스팅 노트 빈 직접 입력·키보드 이동 수정

관련 #6, #21. 직접 입력란에 공백·줄바꿈(IME 조합 중 빈 입력 포함)만 남으면 미응답 상태와 비어 있지 않은 freeText가 함께 전달돼 `Non-answer contains observations`가 발생했다. 텍스트 답변 생성 경계에서 공백뿐인 값은 완전한 미응답으로 만들고, 실제 입력 내용의 공백·줄바꿈은 보존한다. 검증기에서 잘못된 상태를 허용하도록 완화하지 않는다.

키보드가 열릴 때 입력란을 무조건 스크롤 상단으로 올리던 처리를 제거했다. 현재 viewport와 키보드의 경계에서 실제 가려진 높이만 이동하고, 키보드가 닫히면 입력 전 스크롤 위치로 돌아간다. 질문/방식 전환 때는 키보드와 복귀 기준을 정리한다. 타이포·색·선택 칩·기본 간격은 변경하지 않는다. 원본 Figma에 없는 키보드 상호작용 보정이며 픽셀 일치 검증으로 주장하지 않는다.

검증: typecheck/lint/질문 계약 검사 통과. 전체 테스트 329개 중 322개 통과, 외부 환경 의존 7개 skip. 추가 회귀는 4주종×2방식의 모든 텍스트 필드에서 빈 문자열·공백·개행·전각 공백, 입력 후 삭제, 초안 복원과 문장 생성에 관찰이 유입되지 않는 것을 검사한다.

Android 검증용 emulator-5556에서 실제 질문 화면 표시를 확인했다. 시스템의 stylus 안내가 개입해 일반 소프트 키보드의 열림/닫힘 전체 시각 검증은 완료하지 못했다. 사용자의 Galaxy 실제 세션/기록은 변경하지 않았다. 삼성 키보드와 iOS 키보드 실제 상호작용 검증은 남아 있다.

## 글자 잘림·완료 키 보정 · #124 · 2026-10-26

질문/세부 향/문장 수정의 공통 TextInput에 `returnKeyType=done`, `submitBehavior=blurAndSubmit`을 지정했습니다. 완료는 입력을 유지하고 키보드를 닫으며 질문 이동/저장을 호출하지 않습니다. 여러 줄 값의 표시·기존 값 보존은 유지합니다. 입력창은 최소 64dp, 좌우/상하 16dp, lineHeight 24 및 Android font padding으로 한글 placeholder의 위쪽 잘림을 보정했습니다. 사용자 오류 수정에 따른 확장 규격이며 Figma 원본과 완전히 일치한다고 주장하지 않습니다.

iOS 26.5 iPhone 17 Pro 개발용 fixture에서 위스키 가볍게 5/5의 placeholder가 온전히 보이는 것을 확인했습니다. 한국어 소프트 키보드로 `부드러움`을 입력하고 `완료`를 눌렀을 때 키보드가 사라지고 답변/5/5 단계가 유지됩니다. 서버 저장 없는 격리 화면으로 실제 사용자 기록은 수정하지 않았습니다. 증거는 공개 저장소에 포함하지 않는 `artifacts/qa/tasting-done/ios-korean-done-visible.png`, `ios-done-keeps-answer.png`입니다.

Android API 37 개발용 fixture에서도 placeholder 잘림 해소는 시각 확인했습니다. 일반 소프트 키보드의 Done 입력 완료 검증은 에뮬레이터 창/스타일러스 설정 문제로 아직 남아 있습니다. 삼성 키보드 실기기·다른 향/문장 수정의 전체 네이티브 상호작용 역시 별도 검증합니다. 전체 검사: 372개 중 364 통과, 외부 환경 의존 8 skip, 실패 0.

### 추가 iOS 완료 검증
동일 development build에서 문장 직접 수정 입력란도 한국어 `완료`로 키보드만 닫히고 편집 중인 문장이 남는 것을 확인했습니다. 와인 자세히 3/11의 다른 향 입력란은 빈 상태에서 완료 → 다음을 실행해 오류 없이 4/11로 이동했습니다. 개발용 fixture이며 실제 저장은 호출하지 않습니다. `ios-empty-aroma-done-next.png`를 로컬 증거로 보관했습니다.

2026-10-26 최신 코드의 실제 로컬 Auth/DB/Storage 통합 테스트도 별도로 실행했습니다. 기록/사진/노트 저장·메뉴판 수정/추천·술장 cursor/사용자 격리·합성 계정 삭제·manifest 기반 정리 6개 모두 통과했고 skip은 없었습니다. 이 결과는 Android 키보드 실기기 검증을 대체하지 않습니다.
