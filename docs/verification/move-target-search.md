# 기록 이동 검색의 응답 순서 보호 · #150

이전 구현은 더보기 목록 추가만 검색어 문자열로 검사하고 로딩/오류/더보기 상태는 무조건 갱신했습니다. A→B→A 검색은 같은 문자열이어서 처음 A의 늦은 페이지도 새 A 목록에 들어갈 수 있었습니다.

이동 대상 목록을 요청 세대별 pager로 분리했습니다. 검색 변경/재시도/의존 loader 교체/언마운트는 이전 세대를 취소하고, 성공·실패를 현재 세대에만 반영합니다. 더보기 중복 탭은 동기적으로 합치고 겹치는 행은 ID로 중복 제거하며 서버 offset은 원본 행 수로 전진합니다. 검색이 실제로 달라질 때 즉시 취소하고 기존250ms 입력 대기를 유지합니다. 같은 값을 다시 전달한 이벤트는 진행 중 요청을 취소하지 않습니다. 새 검색 중에는 이전 검색의 더보기·오류를 표시하지 않습니다.

React 점검: pager는 loader별 useMemo, publish는 안정적인 setState, effect cleanup은 timer 해제와 cancel입니다. 새 라이브러리·데이터 권한·Figma 토큰/화면 레이아웃 변경은 없습니다. 실제 이동 확인/저장 요청과도 분리합니다.

## 검증

지연 Promise를 제어하는 회귀5개로 A→B→A의 늦은 페이지, 이전 오류가 새 로딩을 덮는 경우, 중복 더보기/겹치는 행/offset, 취소 후 오류와 재시도, 취소 후 첫 페이지 성공/추가 요청 차단을 확인했습니다. 구현을 그대로 비교하는 문자열 테스트 대신 실제 비동기 응답 순서와 최종 목록/상태를 검사합니다.

실제 iOS17Pro/iOS26.5 개발 미리보기에서 `글렌`→`맥주`→`글렌` 검색의 해당 결과 교체·완료 후 검색어 유지/키보드 닫힘을 확인했습니다. 서버 호출 없는 명시적 fixture입니다. UI fixture는 응답을 지연하지 않으므로 네이티브에서 늦은 원격 페이지를 재현했다고 쓰지 않습니다. 지연 응답 경계는 도메인 회귀로 검증했습니다. 로컬 증거는 ignored `artifacts/qa/move-search/ios-search-roundtrip.png`입니다. 실제 사용자 기록은 이동하지 않았습니다.
