# 가격 오인식 행 보존 · geometry-v3

Android ML Kit가 통화 기호를 `%`, `l`, 숫자로 읽으면 geometry-v2는 가격을 만들지 않는 대신 술 행 자체도 누락했다. 실제 두 사진 native→server 실행에서 iOS 12항목/Android 7항목으로 차이가 났다.

## 최종 동작

- 별도 금액 셀의 `12,000%`, `25,000l`, `90,0002`, `₩90,0002` 등은 가격으로 확정하지 않는다. 이름·원본 line ID를 남기고 가격 null, confirmed false, productId null로 반환한다.
- 양쪽 열이 이름→금액 구조이고 명확한 gutter가 있으면 손상된 금액도 열 경계로 사용한다. 옆 열의 정상 가격을 가져오지 않는다.
- 손상된 금액 셀은 용량 추출에서 제외한다. `25,000l`을 000l 같은 용량으로 만들지 않는다.
- 금액 없이도 카탈로그 이름 후보와 맞는 이름은 미확정 후보로 남긴다. WHISKY 같은 제목, 일반 설명, 빈티지 연도, 30ml만 있는 행은 그대로 raw OCR에 둔다. 미지의 가격 없는 이름을 모두 자동 추출하는 기능은 아니다.
- 기존 UI의 ‘가격 미확인’ 표시·수정 폼을 사용한다. 인식 결과 확인과 제품 선택을 건너뛰지 않는다.

## 검증

- 전체 검사 211개 중 207 통과, 실제 HTTP 환경 전용 4개 skip.
- 금액 suffix/원본 불변/열별 출처/제목 제외/실제 Android OCR 재생 회귀 추가.
- 실제 로컬 Auth→Edge HTTP에서 Android OCR 6행이 유지되고 메이커스 마크 가격 null·미확정인지 확인한다. 생성 번들로 Storage/메뉴/계정 정리 통합 3개를 실행한다.
- 실제 iOS Vision v2 및 Android ML Kit 사진 2장→서버→수정 복구→노트 근거 추천까지 각 11단계 통과: [iOS](menu-price-review/ios-native.json), [Android](menu-price-review/android-native.json). 양 플랫폼 모두 12후보. 이름 정확도/가격 정확도 100%라는 뜻은 아니다.
- 이전 Android baseline의 두 열 메뉴 가격 정답은 2/6→3/6이다. 손상된 금액 셀을 별도 열로 나누면서 정상 가격 9,000의 이름이 옆 열에 섞이지 않은 효과다. 손상된 금액 자체를 고친 결과가 아니다. iOS 6/6은 유지한다.

관리형 개발 프로젝트는 아직 geometry-v2 배포 상태다. 현재 브라우저 접근이 비활성화돼 geometry-v3는 로컬 검증 및 draft PR 상태이며 관리형 배포를 완료했다고 주장하지 않는다. 기존 노트/기록 UI와 Figma 원본은 변경하지 않았다.
