# 근거 사진 링크의 묶음 발급

취향·추천 근거 사진은 기록 ID를 중복 제거해 최대 200개 조회하고 소유자/ready 조건 및 RLS를 유지한다. 정렬된 첫 사진만 사용하고 요청하지 않은 기록 ID나 다른 소유자 경로는 제외한다. 서로 다른 경로를 한 번의 createSignedUrls 호출로 발급받으며 유효 기간은 기존 300초다. 반환 순서에 의존하지 않고 path로 대응한다. 개별 실패·요청하지 않은 path는 사진 매핑에 포함하지 않는다.

사진 목록은 20초에 취소 신호를 보낸다. Storage batch 요청은 SDK에 per-call abort가 없어 UI 기다림을 10초로 제한한다. 늦은 발급 결과를 화면에 게시하지 않지만 네트워크 요청 자체 취소를 보장하지 않는다. 기존 UI는 사진 실패를 빈 이미지 매핑으로 처리하고 텍스트 근거를 유지한다. 새 화면·토큰·TTL 변경은 없다.

실제 설치된 Supabase SDK와 제어된 transport로 1회 batch, 첫 사진/중복 제거, 응답 역순, 부분 실패, 요청하지 않은 기록/path·외부 owner 제외, 빈 입력, 미응답 시간 제한·늦은 응답 폐기 회귀를 확인했다. 실제 Storage HTTP에는 소유자 batch URL 발급→바이너리 읽기, B가 A 기록을 요청하거나 owner 인자를 A로 바꿔도 RLS 차단되는 검사를 추가했다. 해당 HTTP 검증은 CI 결과로 구분한다. 관리형 사용자 프로젝트의 실제 계정·실기기 단절 E2E는 별도이며 소셜 로그인 설정은 여전히 필요하다.
