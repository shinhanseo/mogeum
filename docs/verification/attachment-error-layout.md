# 사진 교체 실패 화면 (#122)

Android native 장애 검증에서 보관한 사진이 카드 가로 전체로 커져 오류가 스크롤 아래에 숨었다. pending 사진에 기존 RecordEditScreen의 84×112 세로 사진 크기를 재사용하고, 서버/충돌 오류를 스크롤 밖의 재시도 버튼 바로 위로 옮겼다. 선택 전의 현재/새 사진 비교, 공통 Button, 24px 여백, 색상·타이포 토큰과 저장 요청 계약은 유지한다.

## 디자인 근거

2026-10-26 Chrome native로 04의 22(4:4343)를 열고 사진 레이어4:4355의 88×112를 직접 확인했다. 기존 앱 편집 사진은 84×112이며 이번 대기 사진에는 이 앱 구성과 3:4 cover를 재사용한다. 원본 프레임·측정은 로컬 artifacts/qa/composer-draft/figma-edit-photo-measurement.png에 보관한다. Figma MCP는 재인증 필요, 확장 브라우저는 연결 timeout이라 Chrome UI를 이용했다.

실패/pending 상태는 원본에 없는 확장 상태이므로 원본과 픽셀 일치한다고 주장하지 않는다. 사진은 사용자 동적 이미지이며 새 정적 에셋이나 장식을 추가하지 않았다.

## 검증 범위

`npm run check`: 372개 중 364 통과, 환경 의존 8 skip, 실패 0. 이는 시각 검증을 대신하지 않는다. 실제 Android 서버 중단/재시도 결과는 write-deadlines/README.md에 있다. iOS와 큰 접근성 글자는 별도 검증이 필요하다.

수정 후 같은 Android native에서 사진을 다시 선택하고 gateway를 50초 중지했다. 별도 스크롤 없이 84×112 미리보기, 전체 오류 문장, 활성화된 재시도 CTA가 함께 보이는 것을 확인했다. android-photo-error-layout-fixed.png에 캡처를 보관한다. 서버는 watchdog으로 복구했다.

수정 후 재시도도 상세의 실제 사진 표시로 완료됐다. 해당 합성 계정은 경험 3개/사진 2개를 유지했고 사진 추가·교체 두 작업의 receipt는 2개였다. 사진 교체가 새 마신 경험을 만들거나 중복 사진 행을 추가하지 않았다.
