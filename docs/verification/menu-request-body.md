# 메뉴판 요청 본문의 점진적 한도 검사

인증된 메뉴 해석/추천 요청에서 body 전체를 text()로 먼저 읽던 부분을 stream reader로 바꿨다. 기존 600,000 UTF-16 코드 유닛 제한은 유지하고 읽는 도중 초과하면 reader를 취소해 TOO_LARGE/413을 반환한다. UTF-8 바이트도 1,800,003까지 제한한다(문자당 최대 3바이트와 선행 BOM 3바이트). Content-Length가 없거나 작게 적혀 있어도 실제 수신량을 검사한다. 큰 Content-Length는 본문 누적 없이 거절한다. 사진/줄·메뉴 개수 검증과 인증 순서는 변경하지 않는다. 기존 다른 validation 오류의 상태 코드도 유지한다.

한글/emoji를 한 바이트씩 나눈 stream, 정확한 문자 경계와 한 글자 초과, Content-Length 누락/과소 선언, 바이트 한도/명시적 취소, 빈 body·읽기 오류, 선행 BOM 회귀 6개를 추가했다. HTTP 검증에는 인증 후 JSON 문자열 600,000자 입력의 encoding 포함 한도 초과→413/TOO_LARGE를 추가했다. 실제 함수 HTTP 결과는 CI로 확인한다. 단위 테스트는 실제 브라우저·물리 기기 네트워크 부하 측정이 아니며 플랫폼의 요청 chunk 자체 할당을 통제하는 것은 아니다. 사용자 OCR 원문/예외 내용은 새로 기록하지 않는다.

관리형 함수에는 재배포가 필요하며 현재 배포 완료를 주장하지 않는다. 화면·사진 준비·추천 규칙 변경 없음.
