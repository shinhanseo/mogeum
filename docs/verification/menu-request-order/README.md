# 메뉴판 저장과 재진입 순서

메뉴판의 기기 저장 큐만으로는 서버 응답을 기다리는 동안 새 화면이 이전 revision을 읽는 일을 막지 못했다. MenuFlow의 submitMenu와 device의 restoreMenu가 계정별 공유 요청 큐를 사용한다. 기기 메타데이터 쓰기·파일 정리는 기존 별도 큐로 처리한다.

- 서버 저장 진행 중 취소·이름/가격 수정·화면 종료 후 복원: 이전 응답의 영수증 저장을 기다린 뒤 revision 1과 수정한 값으로 복원하고 revision 1로 다음 저장.
- 서버 응답 유실: pendingSave의 원래 이름을 그대로 재전송한 다음 수정한 이름으로 후속 저장. 오류로 큐가 막히지 않음.
- 취소된 대기 요청: pendingSave가 있어도 서버 요청과 메타데이터 쓰기 0회. 변경 전에는 서버 재전송 1회가 발생해 신규 회귀 테스트가 실패함을 확인.
- 다른 계정의 큐는 앞선 계정의 응답을 기다리지 않음.

실제 submitMenu와 createMenuStore에 지연 Promise·기기 저장 대체 포트를 연결한 회귀 테스트다. 네이티브 화면을 실제 닫고 다시 여는 기기 조작이나 관리형 서버 지연 검증을 대신하지 않는다. 화면·타이포·레이아웃은 변경하지 않았다.

`npm run check`: 타입·린트·테이스팅 계약 통과, 285개 테스트 중 279 통과·환경 의존 6 skip. 서버 응답과 기기 영수증 쓰기를 각각 지연해 재진입이 둘 다 기다리는지 확인했다.
