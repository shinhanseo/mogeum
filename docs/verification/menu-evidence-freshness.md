# 추천 근거 최신 상태와 사진 링크 갱신

## 변경

private 사진 링크는 300초 유효하다. 이전에는 화면 재진입/앱 활성 시 taste hash가 같으면 기존 링크를 그대로 사용했다. 이제 같은 기록이어도 링크를 새로 받고, 메뉴 화면이 열린 동안 240초마다 갱신한다. 화면을 벗어나거나 앱이 비활성이면 주기 요청을 하지 않는다. 늦게 끝난 이전 갱신은 generation/result identity로 무시한다.

추천 응답이 도착한 직후에도 최신 taste hash를 확인하고 근거 사진을 조회한 뒤 결과를 표시한다. 분석 중 기록이 바뀌면 원래 메뉴를 보관하고 재추천을 안내한다. 화면 재진입/앱 복귀/주기 갱신에서 기록이 달라지거나 최신 상태를 확인할 수 없으면 예전 추천과 사진 링크를 숨기고 확인 화면으로 돌아간다.

RPC와 사진 조회는 해당 동작을 시작한 owner/JWT에 고정한 클라이언트로 실행한다. 사진 링크 서명 실패만 발생한 경우 유효한 텍스트 근거는 유지하고 사진 placeholder를 사용한다. 가짜 링크나 public 이미지로 대체하지 않는다. 이미 서명된 링크 자체의 300초 권한을 취소하는 기능은 아니며 기록/계정 삭제 시 서버의 Storage/RLS 정책과 구분한다.

## 검증 범위

pure port 회귀 7개: 같은 hash에서 링크 재발급, 변경된 기록이면 사진 서명 전에 stale, 이미 닫힌 요청, hash 조회/사진 서명 중 계정·요청 전환, 네트워크/잘못된 hash, 사진만 실패 시 텍스트 유지.

실제 Supabase HTTP CI는 동일 Auth/DB hash에서 fresh와 사진 조회 허용, 노트 추가 후 이전 hash의 stale·사진 조회 미실행을 확인한다. 기존 소유권/RLS 테스트를 대체하지 않는다.

화면 배치·컴포넌트·사진 비율 변경은 없다. iOS에서 실사용자 로그인 후 5분 경과된 실제 클라우드 사진의 재발급, Android 런타임, 장시간 백그라운드/네트워크 지연 실측은 미검증이다. 개발 fixture는 서버 호출이 없어 이 검증을 대신하지 않는다. UI에 표시되는 최신 상태는 검증한 시점 기준이며 다른 기기에서 그 직후 생긴 변경까지 원자적으로 동기화한다고 주장하지 않는다.

관리형 서버 배포/Apple·카카오 provider/Gemini 키 설정이 필요한 검증은 계속 미완료로 둔다.
