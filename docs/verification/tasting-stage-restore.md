# 노트 작성 단계 복구 · #130

미리보기까지 진행한 로컬 합성 와인 기록을 앱 종료 후 다시 열면 마지막 질문 5/5로 돌아가는 것을 iOS에서 재현했습니다. 기존 답변/문장은 보존됐지만 화면 단계가 초안에 없었습니다.

계정·기록별 기존 초안에 선택적 `stage`를 보관합니다. 미리보기 진입, 문장 수정 진입/적용/취소, 답변 수정과 방식 변경 때 화면 단계를 함께 갱신합니다. 편집 화면 진입 직후에도 editBuffer를 보관해 아직 타이핑하지 않았거나 빈 문장으로 편집한 경우를 구분합니다. 서버 저장·질문 데이터/버전은 바꾸지 않습니다.

이전 초안은 기존 질문/편집 fallback을 유지합니다. 전송 pending이 있으면 stage와 관계없이 수정 불가 미리보기가 우선입니다. 잘못된 stage는 복원 경계에서 거부합니다. 4주종×2방식의 영속화/복원, 빈 편집, 취소 원문 복원, 질문 복귀, 이전 초안과 pending 우선순위를 회귀 검사합니다. 전체 check: 376개 중 368 통과·외부 환경 8 skip·실패 0.

iOS 26.5 실제 development build + 로컬 Supabase 합성 계정에서 아래를 확인했습니다.

- 와인 미리보기 → terminate/launch → 동일 기록 재진입: 미리보기와 5줄 원문 유지.
- 문장 직접 수정 진입 후 타이핑 없이 terminate/launch → 편집 화면과 원문 유지.
- 복구한 편집 취소 → 원문 미리보기 복귀. 저장 버튼은 누르지 않았습니다.

증거는 무시된 로컬 `artifacts/qa/tasting-done/ios-preview-stage-restored.png`, `ios-editor-stage-restored.png`에 보관했습니다. Android·실기기·실제 빈 편집 버퍼 종료/재시작·계정 전환 전체 UI는 남아 있습니다. 현재 EAS build Android 6/iOS remote 4는 이 수정 이전 소스이므로 이 기능을 포함했다고 표시하지 않습니다.
