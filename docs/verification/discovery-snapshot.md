# 다음 한 잔 · 기록 버전 일관성

취향 근거 snapshot과 전체 음용 이력을 페이지로 따로 읽는 사이 기록이 추가·수정·삭제될 수 있었다. 첫 snapshot의 전체 기록 hash/개수를 고정하고, 추천을 만든 뒤 같은 JWT의 `taste_summary_context`를 다시 읽어 둘 다 같은 경우에만 반환한다. 바뀌면 HTTP409 `TASTE_CONTEXT_CHANGED`, 최종 확인 자체가 실패하면503이다. 자동 반복 생성·기록 쓰기·외부 AI 호출은 없다.

앱은409와 해당 고정 machine code가 함께 있을 때만 ‘내 기록이 바뀌었어요’ 안내를 사용하고 이전 추천을 지운다. 알 수 없는 오류 응답 원문은 표시하지 않는다. 기존 공통 오류/재시도 UI를 사용한다.

이 검사는 조회 도중의 혼합 snapshot을 감지한다. 여러 HTTP 요청을 하나의 DB 트랜잭션으로 만드는 것은 아니며 최종 확인 이후의 변경까지 막는다고 주장하지 않는다. 앱 복귀/다시 진입 때의 재조회도 함께 유지한다. 북마크는 감각 근거가 아니므로 taste hash에 포함하지 않는다.
