# 메뉴판 동적 카탈로그 서버 계약 · #175

`menu-recommend` parse/recommend 요청에 `catalogVersion: shared-catalog-v1`을 명시하면 인증 사용자의 RLS로 검증 제품만 조회한다. 정적 배열 밖 새 제품도 별칭/판본 확인·사용자 확정·내 기록 비교에 사용할 수 있다. 응답에 동일 카탈로그 문서를 포함한다. 제품 ID만으로 매칭하지 않고 메뉴 이름의 정확한 별칭 후보에 속하는지 검사한다. 지원하지 않는 빈티지는 기본 제품으로 임의 대체하지 않는다.

가격·용량·원본 lineIds는 기존 OCR/사용자 확인 계약을 유지한다. 제품 카탈로그는 금액을 생성하거나 메뉴 밖 제품을 추가하는 근거가 아니다. 카탈로그 조회는 ID cursor 200개 단위·최대1000개이고 인증/조회/비교 전체에25초 제한을 적용한다. 실패 시 일부 제품을 조용히 반환하지 않는다.

버전 없는 기존 앱은 이전 응답을 유지한다. **현재 앱의 메뉴 편집·제품 선택·근거 UI는 아직 정적 카탈로그를 사용한다.** 이 변경은 서버 선행 계약이며 앱의 동적 메뉴 기능 완료가 아니다. 앱의 결과 계약·재진입/초안 복구·선택 화면을 함께 전환한 뒤 opt-in한다. 실제 Gemini 제품 조사/추천이나 자동 verified 승격도 포함하지 않는다.

## 검증 · 2026-10-27

- 단위: 신규 제품 별칭·판본·빈티지 모호함·원문 가격/용량/좌표·빈 취향에서 근거 생성 금지.
- 실제 로컬 Auth/DB/Edge: 합성 제품 candidate 숨김→verified 승격→메뉴 해석→사용자 확정 ID→추천, 이름과 ID 불일치 차단, 구버전 응답 확인. 합성 계정·제품 정리 완료.
- 배포용 함수 번들로 실제 HTTP8/8통과, 원본 소스 복구 확인.
- iOS/Android 동적 메뉴 UI 검증·관리형 서버 배포는 아직 수행하지 않았다. 기존 네이티브 OCR 정확도 결과는 이번 테스트가 대체하지 않는다.
