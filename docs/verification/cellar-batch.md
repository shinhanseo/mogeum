# 술장 비공개 사진 링크 묶음 조회

기존 홈은 술장 전체 metadata를 100개씩 읽은 뒤 대표 사진마다 signed URL 요청을 병렬로 실행했다. 이제 고유 사진 경로 100개씩 순차 발급한다. 205개 사진에서는 발급 호출 205개 대신 3개다. 이미지 자체를 내려받는 요청 수를 줄였다는 뜻은 아니다.

## 동작

술장 조회는 각 페이지 20초, 링크 발급은 각 묶음 10초로 대기를 제한한다. SDK Storage에는 개별 abort 옵션이 없어 링크 발급은 늦은 결과를 무시하고 timer를 정리한다. 네트워크 전송 자체를 취소했다고 주장하지 않는다. 화면 focus/owner가 바뀌면 이미 시작한 작업의 결과를 버리고 다음 페이지/묶음을 시작하지 않는다.

응답 순서가 달라도 경로별로 연결하고 요청하지 않은 경로·부분 오류는 제외한다. 다른 owner의 metadata는 결과에서 제외하고 발급 대상도 owner/records 아래 경로만 허용한다. 서버 RLS/Storage 권한 검사는 유지한다. 한 묶음의 오류는 해당 사진만 기존 사진 없음 대체 상태로 처리하며 다른 사진과 기록은 보존한다. 취향 근거 사진과 같은 bounded signing 함수를 사용한다.

## 검증

- 205개 합성 metadata/사진 경로: 페이지 0/100/200, 링크 묶음 100/100/5 및 마지막 기록/사진까지 유지.
- 묶음 실패 후 뒤의 성공 결과 유지, 계정 전환 중 늦은 응답 차단, 추가 요청 중단, 중복/타인 row 제외 회귀.
- 기존 실제 SDK transport 기반 순서 역전·부분 실패·10초 timeout 회귀도 같은 공통 함수를 검사한다.
- 실제 로컬 Auth/Storage HTTP에서 대표 사진 링크 묶음 발급 후 바이너리를 읽는 회귀를 추가했다.
- iOS·Android native 로컬 합성 계정으로 새 술장 loader→Storage 발급→바이너리 읽기를 확인하고 기존 메뉴/기록 경로까지 12단계 통과: [iOS](cellar-batch/ios-native.json), [Android](cellar-batch/android-native.json).

## 남은 범위

현재 metadata는 기존처럼 전체를 읽으므로 모든 기록의 로컬 검색/필터가 유지된다. 화면 진입 시 metadata/링크를 모두 기다리는 구조와 signed URL 5분 이후의 갱신은 별도 개선이 필요하다. 이것은 서버 cursor 기반 무한 페이지 조회를 완료한 변경이 아니다. 205개 검증은 자동 합성 테스트이고 실제 native 검증은 작은 합성 술장이다. 선반·글꼴·사진 비율·바텀탭 레이아웃과 Figma는 변경하지 않았다.

전체 검사: 216개 중 212 통과/실제 서버 환경 전용 4 skip. 실제 HTTP suite는 3/3 통과/skip 0. native 검증용으로 생성한 로컬 합성 계정 4개는 private manifest 기반으로 정리했다.
