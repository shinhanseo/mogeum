# 같은 술의 이전 기록 비교

2026-11-06. 작성 과정은 유지하고, 저장 후 열리는 술 상세에 직전 경험과의 비교를 추가한다. 기존 날짜별 기록과 `한 번 더 기록하기`도 유지한다. 비교는 추가 AI 호출 없이 확정된 원래 선택값으로 생성한다.

- 상세의 기존 최근 100개 기록 목록에서 현재 기록 다음의 직전 경험을 선택한다. 날짜 내림차순, 동일 시각이면 ID 오름차순의 기존 안정 정렬을 따른다. 100개 범위 밖의 오래된 기록에는 비교를 만들지 않는다.
- 이전 기록은 사용자 ID와 술장 항목 ID를 모두 제한해 조회한다. 비교 로딩 실패는 현재 기록 조회를 실패로 바꾸지 않고 별도 안내한다.
- 같은 주종·노트 모드·v2 카탈로그·현재 입력 리비전과 일치하는 확정 노트만 감각 비교한다. 와인 빈티지가 다르면 감각 비교를 생략한다. 다른 모드끼리 답변을 임의로 대응시키지 않는다.
- 양쪽에 직접 답한 향·맛·질감·여운·도수감만 비교한다. 질문 분기에서 비활성인 답, 건너뛰기, 모름, 자유문장 추정은 제외한다. 세부 향은 양쪽에 세부 선택이 있을 때 비교하며 한쪽이 계열만 고르면 계열 수준으로 비교한다.
- 달라진 항목은 최대 3개를 표시한다. 같은 선택의 개수와 두 기록에 모두 있는 재음용 의향도 표시한다. 잘 마시게 됐다거나 취향이 발전했다는 판단은 하지 않는다.
- 작성 중에는 이전 답변을 보여주지 않는다. 이전 기록 보기에서 해당 날짜 상세로 이동한다.

검증: 단위 테스트(누락·모름·모드·빈티지·확정 리비전·다른 술·세부 향) 및 전체 check. 격리 로컬 Supabase에서 임시 사용자로 같은 술의 두 기록과 노트를 실제 RPC로 저장하고 loadRecordDetail의 비교 결과/기록 목록을 검증 후 사용자 삭제. iOS 시뮬레이터에서 합성 데이터 비교 섹션의 배치·줄바꿈 확인. 원본 Figma에 없는 상태를 기존 토큰과 Button으로 추가했으며 Figma 일치 검증은 하지 않았다. Android 실기기 검증 미실행.
