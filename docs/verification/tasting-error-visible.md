# 긴 노트의 저장 실패 안내 · #159

iPhone SE 3세대 / iOS 26.5 / 375×667pt development build의 `/dev/tasting` 전통주 심화 미리보기에서 긴 문장을 직접 편집했다. 고정 `노트 저장` 버튼을 누르면 의도적으로 실패하는 fixture다. 기존 구현은 오류를 긴 본문 맨 아래에 추가해 현재 화면에서는 보이지 않고, 답변/문장 수정만 비활성화돼 실패 이유를 알기 어려웠다.

오류가 생기면 본문 끝으로 스크롤하고, 오류 때문에 콘텐츠 크기가 바뀐 뒤에도 위치를 맞춘다. 같은 문구의 반복 실패도 새 오류 상태로 처리한다. 안내의 기존 위치·문구·타이포·버튼과 서버 저장/재시도 계약은 유지한다. Figma 원본과 새로 픽셀 비교한 변경은 아니다.

동일한 긴 편집 문장으로 수정 전 오류가 가려진 상태와 수정 후 오류 전문 및 고정 저장 버튼이 함께 보이는 상태를 CUA 캡처했다. 실제 버튼을 다시 눌러 즉시 같은 실패가 반복돼도 안내가 보이는 것을 확인했다. 반복 실패 전에 본문 상단으로 이동시키는 드래그는 시뮬레이터 입력이 반응하지 않아 그 별도 조건까지 통과했다고 계산하지 않는다.

로컬 증거: git ignored `artifacts/qa/tasting-error-visible/ios-before-hidden.png`, `ios-after-visible.png`. 서버 요청/실제 사용자 기록 변경은 없다. fixture는 내용을 기기에 영속화하지 않으므로 이 검증을 초안 복구나 서버 재시도 성공 증거로 쓰지 않는다. Android·물리 기기·확대 글자에서 새 오류 노출은 추가 검증 대상이다.

`npm run check`: 타입/린트/카탈로그 검사 및 테스트 **403개 중 395 통과, 환경 의존 8 skip, 실패 0**. 단순 스크롤 UI를 복제하는 단위 테스트 대신 재현한 네이티브 화면으로 확인했다. 현재 배포된 Android code9/iOS simulator7은 이 수정 전 소스다.
