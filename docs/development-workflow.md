# AI 작업 전달과 PR

## 한 이슈의 흐름

이슈와 문서 확인 → 선행 의존성 확인 → 기능 브랜치 → 타입/DB 계약 → 사용자 흐름 구현 → 관련 검증 → PR → 검증된 상태 보고. 다음 이슈로 넘길 계약과 환경 미설정 항목을 남긴다. 사용자가 코드를 직접 작성하지 않더라도 검증 없이 전체 기능을 main에 합치지 않는다.

## 에이전트에게 줄 시작 지시 예시

> AGENTS.md와 이슈 #번호를 읽고 선행 작업을 확인해라. 해당 이슈의 사용자 흐름을 앱·DB·서버까지 연결하고 관련 검증을 실행해라. 실제 연결되지 않은 경로를 fixture로 숨기지 말고, PR에 변경 화면·검증 결과·미해결 항목을 정리해라.

실제 PR을 만든 경우 이슈와 연결한다. 완료 조건을 충족하고 검증 증거를 남긴 뒤 닫는다. 담당 에이전트가 늘어나도 같은 파일/스키마를 동시에 수정하지 않게 작업 경계를 잡는다. 인증·패키지 초기화·스키마 변경·공통 UI·OCR 계약은 다른 기능보다 먼저 조율한다.

## PR 완료 조건

- 이슈가 설명한 사용자 행동이 끝까지 동작한다.
- 관련 데이터가 재실행 후 남고 사용자가 바뀌면 분리된다.
- 로딩/실패/빈 상태/취소가 있고 AI 실패가 기본 기록을 막지 않는다.
- 타입 검사·린트와 의미 있는 도메인 검증을 수행했다. 미실행 항목은 이유를 쓴다.
- 변경 화면은 스크린샷/짧은 동영상으로 확인한다. iOS/Android 확인 환경을 분리 기록한다.
- 새 환경 변수·계약·마이그레이션·설정은 관련 문서에 반영한다.
- 비밀키/개인 데이터/전체 화면 캡처 속 다른 앱 정보가 Public 커밋에 들어가지 않았다.

## 상태 보고

‘완료/진행 중/환경 연결 필요/제품 결정 필요’를 구분한다. 실행하지 않은 테스트를 통과로 표현하지 않는다. 외부 키 미설정으로 AI 호출이 안 되면 UI 완성과 기능 연결 상태를 분리한다. 데모 seed는 예시임을 명확히 표시한다.
